알고리즘

1. 알고리즘의 개념과 표현

항목내용비고
정의어떤 문제를 해결하기 위해 정해진 일련의 절차나 방법문제 해결의 '설계도'
입력 (Input)외부에서 제공되는 0개 이상의 데이터재료
출력 (Output)적어도 1개 이상의 결과가 나와야 함완성된 요리
명확성 (Definiteness)각 단계는 모호하지 않고 명확해야 함"적당히 넣기" (X)
유한성 (Finiteness)반드시 끝이 나야 함 (무한 루프 방지)영원히 끓이기 (X)
효율성 (Effectiveness)가능한 한 적은 자원(시간, 메모리)을 써야 함가성비

2. 알고리즘 → "라면 끓이기" 비유

알고리즘은 '라면 끓이는 법'과 똑같음.

  1. 입력: 라면 봉지, 물, 냄비, 가스레인지
  1. 절차 (알고리즘):
    • 냄비에 물 550ml를 넣는다.
    • 물이 끓을 때까지 기다린다.
    • 만약(If) 물이 끓으면 면과 스프를 넣는다.
    • 4분 동안 더 끓인다.
  1. 출력: 맛있는 라면

💡 포인트: 같은 라면을 끓여도 사람마다 순서가 다르듯 알고리즘도 '누가 더 빠르고 맛있게 만드느냐'의 싸움

3. 순서도의 기호

순서도 기호의 유래

➊ 타원형 (Terminal: 시작과 종료)

  • 이유: 원래는 '알약(Pill)' 모양에서 유래. 시스템의 외부와 내부를 연결하는 통로라는 의미를 담음.
  • 비하인드: 초기에는 직사각형 모서리를 아주 둥글게 깎아 만든 모양이었는데, 이는 과정(직사각형)과는 명확히 구분되면서도 흐름의 '끝단'임을 시각적으로 부드럽게 표현하기 위함임.

➋ 직사각형 (Process: 처리/실행)

  • 이유: 가장 안정적인 '벽돌'의 모양임.
  • 비하인드: 컴퓨터 과학 이전, 공장의 작업 공정표에서 유래함. 무언가 '만들어지고 있는 상태'나 '작업 중'임을 나타낼 때 가장 흔하게 쓰이던 메모지나 카드 모양이 직사각형이었기 때문임.

➌ 마름모 (Decision: 판단/조건)

  • 이유: '갈림길'을 시각화함.
  • 비하인드: 사각형을 비스듬히 세운 모양으로, 흐름이 한 방향으로만 가지 않고 '옆으로 터져 나갈 수 있음'을 시각적으로 잘 보여줌. 상하좌우 4개의 꼭짓점이 있어 Yes/No 또는 여러 선택지로 뻗어 나가기에 최적화된 구조임.

➍ 평행사변형 (Data: 입력/출력)

  • 이유: 과거 컴퓨터에 데이터를 넣던 '천공 카드(Punched Card)'의 경사진 끝부분을 본뜸.
  • 비하인드: 초기 컴퓨터는 종이 카드에 구멍을 뚫어 데이터를 입력함. 이 카드의 모서리가 비스듬하게 잘려 있었는데, 이를 기호화하면서 평행사변형 모양이 굳어지게 됨.

➎ 육각형 (Preparation: 준비)

  • 이유: 본 작업에 들어가기 전 '장비를 세팅'하는 도구 상자 느낌을 줌.
  • 비하인드: 주로 반복문(For)의 변수 초기화 등에 쓰입니다. 일반적인 처리(직사각형)와는 다른 '특수한 준비 단계'임을 강조하기 위해 각을 더 많이 준 형태를 취하게 됨.

4. 알고리즘의 중요성

알고리즘의 정확성 중요함을 보여주는 사례 : Mariner 1호

  • 사건: 1962년 발사된 Mariner 1호의 실패 사례
  • 원인: 포트란(FORTRAN) 코드에서 루프를 제어하는 문장에 작은 오타(콤마 , 대신 마침표 . 사용)
    • DO 3 I = 1, 3 (정상적인 루프 문)
    • DO 3 I = 1. 3 (오타가 포함된 문장)
  • 시사점: 아주 사소한 코드상의 실수 하나가 막대한 비용이 드는 프로젝트를 실패로 이끌 수 있음

데이터를 저장할 때 고유한 키(Key)를 사용하여 즉시 위치를 찾습니다. 데이터가 10개든 100만 개든 찾는 시간은 똑같아 가장 빠름.


O(log n) - 이진 탐색 및 트리 (Trees, Binary Search)
데이터를 반씩 계속 쪼개며 탐색함. 예를 들어 1,024개의 데이터 중 하나를 찾을 때, O(n)은 1,024번의 비교가 필요하지만, O(log n)은 단 10번의 비교면 충분함.


O(n) - 배열 및 리스트 (Arrays & Lists)
데이터 전체를 처음부터 끝까지 한 번씩 확인해야 할 때 발생함. 데이터 양에 정직하게 비례하는 시간 복잡도

O(nlog n) - 퀵 정렬 (Quick Sort)
데이터를 분할하고 정복하는 방식임. 데이터가 많아질 때 O(n^2)보다 훨씬 효율적이어서, 대부분의 프로그래밍 언어에서 기본 정렬 알고리즘으로 채택함.
데이터가 10배 늘어나면 연산량은 약 33배 정도

O(n^2) - 선택 정렬, 삽입 정렬, 재귀 반복
작은 데이터를 정렬할 때는 문제가 없으나, 데이터가 늘어나면 기하급수적으로 느려짐. 실무에서는 대량의 데이터를 다룰 때 이 복잡도를 피하는 것이 관건임.
데이터가 10배 늘어나면 연산량은 100배 늘어남.

선택 정렬(Selection Sort)

코드 한 줄씩 보기

정렬되지 않은 6개의 숫자가 들어있는 리스트를 만듦.

count는 알고리즘이 실행되는 동안 숫자를 서로 몇 번 비교했는지 기록하기 위해 0으로 시작함.

바깥쪽 반복문(i)은 리스트의 처음부터 끝까지 이동하며 정렬된 자리를 확정 지음.

현재 data 리스트에는 [3, 5, 6, 2, 1, 4]라는 6개의 값이 들어있음. len(data)는 6이므로 len(data) - 1은 정확히 5 가 됨. 선택 정렬에서 마지막 남은 하나는 비교할 대상이 없으므로 자동으로 정렬이 완료된 것이나 다름없음. 그래서 굳이 마지막 칸까지 반복문을 돌릴 필요가 없기 때문에 효율성을 위해 보통 len(data) - 1까지만 반복하도록 설계함.

안쪽 반복문(j)은 아직 정렬되지 않은 나머지 데이터 중에서 진짜 가장 작은 값이 어디에 있는지 찾아내는 역할을 함.

왜 i + 1부터 시작하나?

이미 확정된 자리는 건너뜀: i보다 앞에 있는 숫자들은 이미 이전 단계에서 정렬이 완료된 상태임.

나 자신 다음부터 비교함: data[i]가 현재 알고 있는 최솟값(min_idx)이라고 가정하고 시작하기 때문에, 굳이 나 자신과 비교할 필요 없이 다음 칸(i + 1)부터 마지막까지 찾는 것임.

왜 len(data)까지 인가?

끝까지 확인해야 함: 리스트의 마지막 요소까지 전부 확인해봐야 그중에서 진짜 누가 제일 작은지 확신할 수 있음. range(start, end)는 end-1까지 실행되므로, len(data)라고 써야 리스트의 마지막 인덱스까지 검사하게 됨.

찾아낸 가장 작은 값(data[min_idx])과 현재 위치(data[i])의 숫자를 서로 맞바꿈.

notebooks = [4, 7, 6, 5, 3, 2, 1]

def selection_sort(data):
    n = len(data)
    total_comparisons = 0  
    print(f'초기 상태: {data}\n')
    for i in range(n - 1):
        min_idx = i
        step_comparisons = 0 
        for j in range(i + 1, n):
            step_comparisons += 1
            total_comparisons += 1
            if data[j] < data[min_idx]:
                min_idx = j
        data[i], data[min_idx] = data[min_idx], data[i]
        print(f'{i+1}단계: {data} (비교 {step_comparisons}회)')

    print('-' * 30)
    print(f'최종 정렬 결과: {data}')
    print(f'총 비교 횟수: {total_comparisons}회')

1. 변수 초기화 및 준비 단계

  • 리스트 설정: 정렬 안 된 7개의 숫자 [4, 7, 6, 5, 3, 2, 1]를 notebooks 변수에 저장함.
  • 데이터 크기 확인: len(data)를 통해 리스트의 총 길이인 n = 7을 파악함.
  • 카운터 초기화: 전체 비교 횟수(total_comparisons)를 0으로 설정하여 기록 시작을 준비함.

2. 외부 반복문 (바깥 루프: i)

  • 정렬 위치 결정: range(n - 1)을 통해 0번 인덱스부터 5번 인덱스까지 순차적으로 정렬 위치를 지정함.
  • 최소값 인덱스 가중: 현재 위치 i를 가장 작은 값의 위치인 min_idx로 가정하고 시작함.
  • 단계별 비교 횟수 리셋: 각 회전(Step)마다 step_comparisons를 0으로 초기화함.

3. 내부 복문 (안쪽 루프: j)

  • 비교 범위 설정: 현재 위치 다음 칸인 i + 1부터 리스트의 마지막(n)까지 탐색 범위를 설정함.
  • 카운트 누적: 비교 연산이 수행될 때마다 step_comparisons와 total_comparisons를 1씩 증가시킴.
  • 최소값 갱신 조건: data[j]의 값이 현재 min_idx 위치의 값보다 작을 경우, min_idx를 j로 변경함.

i = 0 일 때 (첫 번째 자리에 올 숫자 찾기)

  • min_idx를 0으로 잡음. (숫자 4가 현재 최솟값이라고 가정함.)
  • j는 1번부터 6번 인덱스까지 쭉 훑음. (7, 6, 5, 3, 2, 1 순서대로).
  • 1이 가장 작다는 걸 발견하고 min_idx는 6이 됩니다.
  • 결과: 맨 앞의 4와 가장 작은 1을 바꿈.
  • 출력: 1단계: [1, 7, 6, 5, 3, 2, 4] (비교 6회)

i = 1 일 때 (두 번째 자리에 올 숫자 찾기)

  • 이제 1은 고정임. min_idx를 1로 잡음. (숫자 7이 최솟값이라고 가정함.)
  • j는 2번부터 6번 인덱스까지 (6, 5, 3, 2, 4) 비교함.
  • 2가 가장 작으므로 min_idx는 5가 됨.
  • 결과: 7과 2를 바꿈.
  • 출력: 2단계: [1, 2, 6, 5, 3, 7, 4] (비교 5회)

반복되는 과정

이런 식으로 한 칸씩 오른쪽으로 이동하며 남은 것 중 제일 작은 숫자 찾기를 반복함.

  • 3단계: 6, 5, 3, 7, 4 중 가장 작은 3을 찾아 6과 교체 → [1, 2, 3, 5, 6, 7, 4] (비교 4회)
  • 4단계: 5, 6, 7, 4 중 가장 작은 4를 찾아 5와 교체 → [1, 2, 3, 4, 6, 7, 5] (비교 3회)
  • 5단계: 6, 7, 5 중 가장 작은 5를 찾아 6과 교체 → [1, 2, 3, 4, 5, 7, 6] (비교 2회)
  • 6단계: 7, 6 중 가장 작은 6을 찾아 7과 교체 → [1, 2, 3, 4, 5, 6, 7] (비교 1회)

4. 데이터 교환 및 결과 출력

  • 값 바꾸기 (Swap): 내부 반복문 종료 후, 결정된 min_idx 위치의 값과 처음 가정했던 i 위치의 값을 서로 맞바꿈.
  • 진행 상황 출력: 현재 몇 단계인지, 정렬된 리스트의 상태는 어떠한지, 해당 단계에서 몇 번의 비교가 있었는지 화면에 표시함.

5. 최종 결과 도출
• 정렬 완료: 모든 반복문 종료 후 오름차순([1, 2, 3, 4, 5, 6, 7])으로 정렬된 최종 리스트를 출력함.
• 총 비교 횟수: 데이터가 7개일 때 산출되는 총 비교 횟수 21회(6+5+4+3+2+1)를 최종적으로 확인하며 마무리함.

notebooks = [4, 7, 6, 5, 3, 2, 1]
comparison_count = 0

def quick_sort(data):
    global comparison_count
    if len(data) <= 1:
        return data
    
    pivot = data[0]  # 첫 번째 원소를 피벗으로 설정
    left_side = []   # 피벗보다 작은 원소들
    right_side = []  # 피벗보다 큰 원소들
    
    for i in range(1, len(data)):
        comparison_count += 1
        if data[i] < pivot:
            left_side.append(data[i])
        else:
            right_side.append(data[i])
            
    print(f'피벗 {pivot} 기준 분할: {left_side} < [{pivot}] < {right_side}')  
    return quick_sort(left_side) + [pivot] + quick_sort(right_side)

print(f'초기 데이터: {notebooks}\n')

def sequential_search(data, target):
    count = 0
    for i in range(len(data)):
        count += 1
        print(f'\n{count}번째 비교: {data[i]} == {target}?')
        if data[i] == target:
            print(f'찾았다! 위치는 인덱스 {i}입니다.')

140쪽_해보기6_이진 탐색_마트료시카 인형

notebooks = ['A', 'B', 'C', 'D', 'E', 'F', 'G', 'H']
target = 'E'

def binary_search(data, target):
    low = 0
    high = len(data) - 1
    count = 0
    
    while low <= high:
        count += 1
        mid = (low + high) // 2
        print(f'{count}회차 비교: 중간값 {data[mid]}와 {target} 비교')
        
        if data[mid] == target:
            return count
        elif data[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return count

total_count = binary_search(notebooks, target)
print(f'총 비교 횟수: {total_count}회')

코드 이해

1. 초기 설정 및 전제 조건

  • 정렬된 데이터 준비: 알파벳 순서대로 정렬된 notebooks 리스트(['A' ~ 'H']) 확인.
  • 탐색 범위 지정: 리스트의 시작 인덱스를 low(0), 끝 인덱스를 high(7)로 설정하여 전체 범위를 지정함.
  • 비교 카운터: 탐색 횟수를 기록할 count 변수를 0으로 초기화함.

2. 이진 탐색 원리 (반복문)

  • 중간값(mid) 계산: low와 high의 중간 위치인 mid를 계산함. (소수점은 버리는 // 연산자 사용)
  • 세 가지 경우의 수 비교:
    1. 일치할 경우: data[mid]가 target('E')과 같으면 탐색 성공 및 즉시 종료.
    1. 중간값이 작을 경우: 찾으려는 값이 중간값보다 뒤에 있다는 뜻이므로, low를 mid + 1로 옮겨 오른쪽 절반을 탐색함.
    1. 중간값이 클 경우: 찾으려는 값이 중간값보다 앞에 있다는 뜻이므로, high를 mid - 1로 옮겨 왼쪽 절반을 탐색함.

3. 실행 단계 시뮬레이션 (Target: 'E')

  • 1회차: low=0, high=7 → mid=3 (값: 'D')
    • 'D'는 'E'보다 작으므로 오른쪽 절반으로 범위를 좁힘 (low=4).
  • 2회차: low=4, high=7 → mid=5 (값: 'F')
    • 'F'는 'E'보다 크므로 왼쪽 절반으로 범위를 좁힘 (high=4).
  • 3회차: low=4, high=4 → mid=4 (값: 'E')
    • 'E' == 'E' 일치! 탐색 종료.

4. 최종 출력 및 결과 요약

  • 탐색 효율성 확인: 순차 탐색이었다면 'E'를 찾기 위해 5번 비교했겠지만, 이진 탐색은 단 3회 만에 탐색을 완료함.
  • 알고리즘의 특징:
    • 탐색 범위를 매번 절반씩(1/2) 줄여나가기 때문에 데이터 양이 많아질수록 순차 탐색보다 압도적으로 빠름.
    • 반드시 데이터가 미리 정렬되어 있어야만 정상적인 동작이 가능함.
